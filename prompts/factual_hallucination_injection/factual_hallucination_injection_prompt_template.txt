### GROUND TRUTH AND EXECUTION RULES

1. **Immutable reference:** Treat both `sop_content` and `scenario_json` as verified truth. Never modify `sop_content`, and never change `scenario_json` merely to make the Agent's false claim true. A scenario adjustment is allowed only when a pre-chat attribute must be changed to make the setup coherent; it must not validate the hallucination.

2. **Single-judge focus:** Optimize for conversational realism and causal coherence for the target judge. Do not force an unnatural downstream outcome merely to preserve hypothetical process-compliance judgments. If a hallucinated fact naturally changes eligibility or an action, let subsequent customer, Agent, and ACTION turns follow that claim consistently.

3. **Confident smart confabulation:** The Agent must state the false claim as a fact or confident, helpful-sounding inference. Use plausible extrapolation: a realistic record value, policy parameter, system explanation, or operational cause that fits the conversation but is contradicted by or absent from the verified references. Never use absurd claims, random details, or cartoonish behavior.

4. **No missing-data escape:** Never have the Agent say that it does not have the information, cannot find the data, or is unable to answer. The defect must be a hallucinated assertion, not `missing_data`.

5. **Knowledge boundaries:** The customer knows their own account, tier, order history, and request, so they may naturally question a contradiction about those facts. The customer has no access to internal SOP rules or backend behavior; when the Agent hallucinates policy or system facts, the customer must accept and continue naturally rather than audit the SOP.

6. **Pre-existing defects:** First inspect the base conversation. If it already contains a factual hallucination, set `already_defective` to true, leave every turn unchanged, ignore the requested count and phase, and log every existing defective AGENT/ACTION turn. 7. **Causal propagation:** Rewrite all subsequent turns as needed so the dialogue remains internally coherent and realistic. Do not patch only one line while leaving later turns to contradict the hallucinated claim.

8. **Stealth:** Never add labels or meta-commentary such as `[HALLUCINATION]`, `NOTE:`, `CONFLICT:`, `WARNING:`, `OVERRIDE:`, “as prompted,” or references to this task, judge, SOP defect, or injection.

9. **Turn logging:** Use 1-based sequential `turn_id` values beginning at 1. `injected_turn_indices` and `violations` must identify the exact AGENT or ACTION turns where the hallucination occurs, never CUSTOMER turns. The number of logged violations must equal `total_injected_errors`.

10. **Scenario metadata:** Keep `scenario_json` unchanged and use `scenario_modified: false` with `{{}}` unless a pre-chat setup adjustment is genuinely necessary. If adjusted, record only the changed fields and ensure the adjusted record still contradicts the hallucinated claim.
